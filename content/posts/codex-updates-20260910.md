## はじめに

2026年9月10日、OpenAI Codex CLI の **rust-v0.154.0** がリリースされました。本リリースでは、新モデル GPT-6-Astra の統合、worktree による分離された作業環境の実験的サポート、Windows におけるデーモンサーバー共有機能、インライン質問応答機能など、大きく4つの柱となる新機能が追加されています。

また、プラグインツールの自動リロード、MCP OAuth トークン更新の協調制御、セキュリティ強化（サンドボックス・trust 確立前のヘルパー実行防止）、approval 自動化の堅牢化など、実運用における信頼性と安全性を高める改善が多数含まれています。さらに、非推奨となっていた `codex mcp-server` コマンドが削除されるなど、仕様の整理も進められました。

---

## 注目アップデート深掘り

### 1. 実験的 worktree サポート：並行作業の分離と再開を実現

本リリースでは、複数の作業を並行して進める際に Git の worktree 機能を活用できる実験的機能が導入されました。公式リリースノートには次のように記載されています：

> Experimental worktree support lets you create isolated checkouts for new or forked sessions using `--worktree` or `/worktree`, then browse and resume them.

この機能により、新しいセッションや fork したセッションに対して、分離されたファイルツリー上で作業を進められます。たとえば、`codex exec --worktree` オプションや、TUI 内で `/worktree` コマンドを使って管理された worktree を作成でき、後から TUI のブラウザ機能を使って一覧表示・再開が可能です。

**なぜこの変更が重要なのか**  
大規模なコードベースや複数のフィーチャーブランチに同時に取り組む開発者にとって、ディレクトリを切り替えたり複数のローカルクローンを持つのは煩雑です。worktree を Codex が管理することで、セッション単位で独立した作業環境を保持しながら、必要に応じて素早く復帰できるようになります。リリースノート内の関連 PR (#42652, #43069, #43120, #43286) からは、管理された worktree 作成・一覧取得・TUI でのブラウズ・セッションコマンドへの統合が段階的に実装されたことが読み取れます。

**具体的な使い方**  
公式リリースノートに示された利用方法は以下の通りです：

```bash
$ codex exec --worktree
```

または TUI 内で：

```
/worktree
```

これにより、新規セッションや fork されたセッションごとに分離されたチェックアウト環境が作成されます。作成後は TUI の worktree ブラウザで一覧を参照し、再開したいセッションを選択できるようになっています。

> **Note:** worktree 機能は現在実験的（Experimental）であり、安定化に向けた今後のリリースで仕様が変更される可能性があります。

### 2. Windows でのバックグラウンド Codex サーバー共有とライフサイクル管理

従来、Codex CLI は各セッションごとに独立したプロセスとして動作するケースが多かったですが、本リリースでは Windows 環境において複数のセッションがバックグラウンドの Codex サーバーを共有できるようになりました。リリースノートには次のように記載されています：

> Windows sessions can now share a background Codex server, with daemon lifecycle commands and managed updates.

これにより、複数のターミナルやセッションから同一の app-server デーモンに接続し、リソースの効率化や起動時間の短縮が期待できます。さらに、デーモンのライフサイクル管理コマンドと管理されたアップデート機能が提供されることで、Windows 環境でも Unix 系 OS と同様の運用が可能になります。

**なぜこの変更が重要なのか**  
Windows 上での開発環境は、プロセスモデルやファイルシステムのアクセス制御が Unix 系と異なるため、複数セッションでの安定した共有サーバー運用が課題でした。今回の実装（関連 PR: #42405, #42392）により、Windows でも Codex をデーモンとして常駐させ、起動コストを削減しつつ、アップデートもシームレスに適用できるようになります。特にインフラエンジニアや SRE が Windows ベースの CI/CD 環境や開発用 VM を運用する際、Codex の再起動コストやセッション間の一貫性が向上します。

**具体的な使い方**  
リリースノートには具体的なコマンド例は明記されていませんが、「daemon lifecycle commands」が提供されることが述べられています。これにより、従来 Unix 系 OS で利用されていたデーモン制御が Windows でも可能になったと理解できます。関連 PR (#42364, #42381, #42405, #43308) からは、Windows サンドボックスサービス、グレースフルシャットダウン、シャットダウンファイルからソケットリクエストへの移行などが実装され、Windows 固有のプロセス管理機構が整備されたことが読み取れます。

> **Note:** Windows 向けのサンドボックス機能やデーモン管理は、macOS/Linux と異なる OS レベルの機構を利用しています。詳細な仕様や制約については、公式ドキュメントを参照してください。

## 実用的な活用ポイント

### 日常の開発ワークフローへの影響

本リリースで導入された **インライン質問応答機能** は、開発作業の流れを止めずに疑問点を解消できる点で非常に有用です。リリースノートには次のように記載されています：

> Answer questions inline while Codex continues working, using suggested choices or custom text without losing your main draft.

これにより、Codex が長時間のタスクを実行している最中でも、並行して質問に答えることができ、メインのドラフトやコンテキストを失わずに作業を継続できます。SRE やインフラエンジニアが Terraform の apply や Ansible のプレイブック実行を Codex に依頼している間に、別の質問（たとえばエラーログの解釈やパラメータの確認）に応答する、といったシーンでの活用が想定されます。

### プラグインとツールの動的リフレッシュ

本リリースでは、既存セッションでもプラグインのインストールやアップグレード後に自動でツールがリフレッシュされるようになりました：

> Existing sessions pick up newly installed plugin tools and refresh skills and hooks after external plugin upgrades or rollbacks.

これにより、セッションを再起動せずに最新のプラグイン機能を利用できるため、長時間のデバッグセッションや継続的なインフラ作業において、ツールのバージョン管理やスキルセットの変更が柔軟に反映されます。特に MCP（Model Context Protocol）サーバーの OAuth トークン更新も協調的に処理されるようになり（#42413, #42552）、外部 API との連携が安定します。

### セキュリティと信頼性の向上

公式リリースノートには、起動時の信頼確立前にワークスペース制御下のヘルパーを実行しない仕組みや、macOS サンドボックスでのターミナル入力インジェクション防止が追加されたことが明記されています：

> Startup avoids running workspace-controlled helpers before trust is established, and the macOS sandbox blocks terminal input injection.

これにより、未信頼のリポジトリを開いた際の攻撃リスクが軽減されます。SRE が複数のプロジェクトや外部からクローンしたコードベースを扱う際、意図しない悪意あるスクリプトが実行されるリスクを抑えられます。

## まとめ

rust-v0.154.0 は、新モデル GPT-6-Astra の統合、並行作業を効率化する worktree 機能、Windows でのサーバー共有・デーモン管理など、ユーザー体験と開発効率を大きく向上させる機能が導入されたリリースです。同時に、プラグインの動的リフレッシュ、MCP 連携の堅牢化、セキュリティ面での信頼確立前実行の防止など、実運用で求められる安定性・安全性の改善が多数含まれています。

特に、インライン質問応答やリッチテキストコピー、Guardian 自動承認の精度向上といった細かな改善は、日常的な開発・運用作業における体験の質を高めるものです。一方で、`codex mcp-server` コマンドの削除など、仕様の整理も進められており、今後の Codex CLI のメンテナンス性向上にもつながります。

SRE やインフラエンジニアにとっては、Windows 環境でのデーモンサポートや MCP OAuth 協調更新、サンドボックスの強化により、クロスプラットフォームでの運用やセキュリティ要件の厳しい環境でも安心して利用できる基盤が整いつつあります。worktree による並行作業環境の分離は、複数のインフラタスクやロールバック・ロールフォワード検証を同時に進める際に有用でしょう。

今後のリリースでも、実験的機能の安定化や新モデルへの対応が継続されることが期待されます。
