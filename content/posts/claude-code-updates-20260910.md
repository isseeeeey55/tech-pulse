## はじめに

2026年9月10日、Claude Code v2.1.267およびv2.1.266がリリースされました。v2.1.267では、`maxEffortLevel`設定の追加により全プロバイダーでのリソース消費制御が可能になったほか、大規模セッション復元時のツール呼び出し欠落修正、AWS/Google Cloud認証エラーハンドリングの改善、プロンプトキャッシュの安定性向上など、多数の修正と改善が含まれています。v2.1.266は、v2.1.265で発生したLLMゲートウェイ・プロキシ環境での認証回帰バグを修正するホットフィックスです。

## 注目アップデート深掘り

### maxEffortLevel設定の追加

v2.1.267で、`maxEffortLevel`設定がトップレベルまたは`modelSettings`配下のモデル単位で指定可能になりました。この設定はBedrock、Vertex、Foundryを含むすべてのプロバイダーで、エフォートレベルの上限を設定できます。ユーザーは依然として設定された上限以下の低いレベルを選択可能です。

この機能により、組織全体でのリソース消費を制御しながら、各モデル呼び出しのコストと品質をバランス調整できるようになります。特に複数のプロバイダーを使い分ける環境で、統一的なリソース管理が実現します。

### 大規模セッション復元時のツール呼び出し保持

トランスクリプトサイズが5MBを超える大規模セッションの復元時に、並列ツール呼び出しとそのフック出力が会話から欠落していた問題が修正されました。この修正により、複雑な作業履歴を持つセッションでも、すべてのツール実行履歴が正確に復元されるようになりました。

長時間にわたる分析作業や、多数のツール呼び出しを含む複雑なタスクを中断・再開する際の信頼性が大幅に向上します。

## 実用的な活用ポイント

`--system-prompt-snapshot off`オプションにより、システムプロンプトを会話ごとに記録された内容を再利用せず、リクエストごとに新規レンダリングできるようになりました。プロンプトテキストの調整を反復的に行う際に有用です。

プロンプトキャッシュの安定性向上により、`--system-prompt`や`--append-system-prompt`で開始されたセッションが、システムプロンプトとツール定義を一度だけ記録し、再レンダリングしなくなりました。セッション再開時のMCPツール定義の再送や、モデル切り替え時のツール定義再送が抑制され、キャッシュミスとそれに伴う思考プロセスの欠落が解消されます。

マネージド設定の`allowedHttpHookUrls`、`httpHookAllowedEnvVars`、`allowedChannelPlugins`が読み取り不能な場合、すべてを許可するのではなく何も許可しない動作に修正されました。セキュリティ上のデフォルト挙動が強化されています。

## まとめ

v2.1.267は、リソース消費制御の強化（`maxEffortLevel`設定）、大規模セッションの信頼性向上（5MB超トランスクリプトのツール呼び出し保持）、プロンプトキャッシュの安定化（ツール定義再レンダリング抑制）、認証エラーハンドリングの改善、セキュリティ設定のデフォルト強化など、広範な修正と改善を含むメジャーリリースです。特にプロンプトキャッシュ関連の多数の修正により、MCP/サブエージェント/セッション再開における思考プロセスの欠落が大幅に削減されます。v2.1.266は、v2.1.265で発生したゲートウェイ環境での認証障害を即座に解消するクリティカルホットフィックスです。
