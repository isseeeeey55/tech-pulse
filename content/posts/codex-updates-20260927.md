# OpenAI Codex CLI rust-v0.157.1 リリース情報

![](/images/codex-updates-20260927/header.png)

## はじめに

OpenAI Codex CLI の **rust-v0.157.1**（パッケージバージョン 0.157.1）が 2026年9月26日に GitHub でリリースされました。0.157.0 に対するパッチリリースです。

リリースノート本文は Chores セクションの 1 項目のみで、「提供された PR インデックスが空で、GitHub のタグ比較が 404 を返したため、リリースハイライトを特定できなかった」という自動生成の注記になっています。ただし、本文に掲載されている [比較ページ（rust-v0.157.0...rust-v0.157.1）](https://github.com/openai/codex/compare/rust-v0.157.0...rust-v0.157.1) は現在は正常に表示でき、Windows 向けの修正 4 件が含まれていることを確認できます。本記事では、比較ページのコミット内容をもとに変更点を整理します。

## 注目アップデート深掘り

### Windows でのプロセス起動まわりの修正

比較ページに含まれるコミットは、リリース用コミットを除くと 4 件で、いずれも Windows でのプロセス起動に関するものです。

**コンソールウィンドウの非表示（#48138 / #48238）**
code-mode ホストの起動時（#48138）と、ローカルの MCP サーバーの起動時（#48238）に、コンソールウィンドウが表示されないようになりました。#48138 では、code-mode ホストの起動時に `CREATE_NO_WINDOW` を設定しています。#48238 では、共通のコマンドラッパーに Windows のプロセス作成フラグを渡せるようにし、ローカル MCP サーバーの起動で使っています。

**デーモン起動の修正（#48157 / #48272）**
ジョブメンバーシップが残っている状態でも Windows でデーモンを起動できるようになりました（#48157）。また、デーモン起動時にランチャーの標準入出力を保持しないようになりました（#48272）。コミットの説明によると、デタッチされた Windows デーモンがランチャーの出力パイプを継承すると、ランチャーの終了後も呼び出し側が EOF を待ち続ける状態になっていました。

## 実用的な活用ポイント

### アップデートの判断

今回の変更はすべて Windows 固有です。Windows で Codex CLI を使っていて、MCP サーバーや code-mode ホストの起動時にコンソールウィンドウが表示される、あるいはデーモン起動後に呼び出し側が戻ってこない、といった現象に心当たりがあれば、アップデートの対象になります。macOS / Linux 環境では、比較ページ上で該当する変更はありません。

アップデートは、公式リポジトリの README にあるインストール方法（npm の場合は `npm install -g @openai/codex`）で行えます。

```bash
npm install -g @openai/codex
```

CI などでバージョンを固定している場合は、比較ページのコミット（4 件）を確認したうえで更新を判断してください。

## まとめ

rust-v0.157.1 は、リリースノート本文こそ「ハイライトを特定できなかった」という注記のみですが、比較ページで確認できる実際の変更は Windows でのプロセス起動に関する修正 4 件です。コンソールウィンドウの非表示（code-mode ホスト・ローカル MCP サーバー）と、デーモン起動の修正（ジョブメンバーシップ・ランチャーの標準入出力）が含まれます。Windows 以外の環境では、急いで更新する理由は比較ページ上には見当たりません。
