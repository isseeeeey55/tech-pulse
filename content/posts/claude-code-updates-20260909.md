## はじめに

Claude Code v2.1.265 がリリースされました。このバージョンでは、プラグイン管理の柔軟性向上、テレメトリ機能の拡充、ツール結果の保存上限設定などが実装されています。加えて、サブエージェント再開時のプロンプトキャッシュ再利用の問題、セッション管理に関する複数の不具合、VS Code 拡張機能における非アクティブセッションの自動アーカイブ機能など、30件以上の修正と改善が含まれています。

## 注目アップデート深掘り

### プラグインディレクトリの動的管理

`--plugin-dir` フラグで、複数のプラグインを含むフォルダを直接指定できるようになりました。マニフェストを持つ各子フォルダが個別のプラグインとして読み込まれ、実行中にフォルダを追加・削除すると自動的に検知されます。

従来は個別プラグインのパスを指定する必要がありましたが、今回の変更により、組織やチームで複数のカスタムプラグインを管理する際の運用が簡素化されます。プラグインの追加・削除がディレクトリ操作だけで完結し、Claude Code の再起動が不要になります。

### ツール結果の保存上限と通知

ツール実行結果のディスク保存に 1 GB の上限が設定されました。保存されたファイルが切り詰められた場合、会話内のプレビューにその旨が表示されます。

大量のログやデータを処理するツールを利用する際、ディスク容量の枯渇を防ぎつつ、ユーザーはデータが切り詰められたことを明確に把握できるようになります。

## 実用的な活用ポイント

今回のリリースでは、セッションの安定性と再開性が大幅に向上しています。サブエージェント再開時やプロセスクラッシュ後の復旧において、プロンプトキャッシュの再利用が正常に機能するよう複数の修正が行われました。これにより、長時間にわたる作業セッションでも中断・再開がスムーズになります。

プラグイン管理の改善により、カスタムツールやスキルを柔軟に追加・削除できるようになりました。VS Code ユーザーは、非アクティブセッションの自動アーカイブ機能（デフォルト14日）により、作業履歴を整理しやすくなります。

MCP サーバー接続の安定性も向上しており、レガシー HTTP+SSE トランスポートへのフォールバックや、OAuth クライアント登録のタイミング最適化が実施されました。

## まとめ

v2.1.265 は、プラグイン管理の柔軟性向上とセッション安定性の強化を中心としたメンテナンスリリースです。サブエージェント再開やプロンプトキャッシュ再利用に関する複数の修正により、長時間作業や中断・再開のシナリオが安定しました。プラグインディレクトリの動的管理やツール結果の保存上限設定など、運用性を高める機能も追加されています。VS Code ユーザー向けには非アクティブセッションの自動アーカイブ機能が導入され、作業履歴の整理が容易になりました。MCP サーバー接続やテレメトリ機能の改善も含まれており、全体として安定性と運用性が向上したバージョンといえます。
