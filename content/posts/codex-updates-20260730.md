# OpenAI Codex CLI rust-v0.146.0 リリース解説

## はじめに

2026年7月30日、OpenAI Codex CLI の Rust バージョン **rust-v0.146.0** がリリースされました。本リリースでは、セッション管理の柔軟性向上、プラグインエコシステムの拡充、スレッド履歴のフォーク機能、そしてプロキシ設定の一貫した適用といった多岐にわたる改善が施されています。

主な変更点は以下の通りです：

- `/new` や `/clear` コマンドでのセッション命名、重要なスレッドのピン留め、サイド会話の保持機能
- Agent Plugins マニフェストのサポートと、Amazon Bedrock、Claude Code 向けプラグインマーケットプレイスの拡張
- ページネーション対応のスレッドフォーク機能（一時的なフォークも含む）
- WebSocket 経由でのリモート Code Mode ホスト接続
- 認証、プラグインダウンロード、MCP、リモート実行全体でのプロキシ設定の統一的な適用
- MCP 接続の維持と再接続の改善、ターミナル応答性の向上

本リリースは、日常の開発ワークフローをより柔軟かつ堅牢にする多数の改善を含んでおり、特に複数のスレッドを並行して扱うユーザーや、企業プロキシ環境下で作業するユーザーにとって恩恵が大きい内容となっています。

## 注目アップデート深掘り

### 1. セッション管理の大幅強化：名前付け・ピン留め・サイド会話の保持

本リリースでは、`/new` や `/clear` コマンドを使ってセッションに任意の名前を付けられるようになり、重要なスレッドをピン留めして優先的に表示できるようになりました。さらに、サイド会話（副次的なスレッド）を閉じることなく別のスレッドへ切り替えられる機能が追加されています（#34605, #34840, #35011）。

**なぜ重要なのか**

従来、Codex CLI で複数のトピックを並行して扱う際、スレッドを切り替えるたびに以前のコンテキストが失われたり、再度スレッドを探し出す手間が発生していました。特に長期プロジェクトや複数のタスクを掛け持ちする開発者にとって、スレッド管理の煩雑さは生産性のボトルネックとなっていました。本機能により、スレッドに意味のある名前を付けて整理し、重要なものをピン留めして素早くアクセスでき、複数の会話を同時進行で保持できるようになります。

**具体的な使い方**

リリースノートに記載されている通り、`/new` または `/clear` コマンド実行時にセッション名を指定することで、新しいスレッドに名前を付けられます。またピン留め機能により、頻繁に参照するスレッドを上位固定できます。サイド会話の保持機能により、以下のようなワークフローが可能になります：

```bash
# メインタスクのスレッド
$ /new "インフラコード改修"

# サイドタスクとして別のスレッドを開始
$ /new "ログ調査"

# 元のスレッドに戻る際、"ログ調査"スレッドは閉じずに保持される
```

ピン留めされたスレッドはスレッド一覧の上位に表示され、名前付きセッションはプロジェクトごとの整理を容易にします。これにより、複数の並行タスク間を行き来する際のコンテキストスイッチコストが大幅に削減されます。

### 2. プロキシ設定の統一的な適用とネットワーク透過性の向上

本リリースでは、認証、プラグインダウンロード、MCP 認可、リモート実行、WebSocket、リダイレクト、LM Studio 接続といった全てのネットワーク通信において、設定されたプロキシが一貫して尊重されるようになりました（#34479, #34509, #34655, #34678, #35023, #35056, #35239）。

**なぜ重要なのか**

企業環境やセキュリティ要件の厳しい組織では、すべての外部通信が HTTP プロキシを経由する必要があります。以前のバージョンでは、一部の通信経路でプロキシ設定が正しく適用されず、認証失敗やプラグインダウンロードエラー、MCP サーバーへの接続失敗といった問題が発生していました。本改善により、Codex CLI の全ての通信がプロキシ設定を統一的に参照するようになり、企業プロキシ環境下でも安定した動作が保証されます。

**具体的な使い方**

システムのプロキシ設定（環境変数 `http_proxy`、`https_proxy`、`CARGO_HTTP_CAINFO` 等）が Codex CLI の全ての機能で自動的に適用されます。例えば：

```bash
# プロキシ環境変数を設定
$ export http_proxy=http://proxy.company.com:8080
$ export https_proxy=http://proxy.company.com:8080

# Codex CLI のすべての通信が自動的にプロキシを経由
$ codex auth login       # 認証もプロキシ経由
$ codex plugin install   # プラグインDLもプロキシ経由
```

リリースノートによれば、リダイレクト時のプロキシルート再解決（#34479）、リモートプラグイン取得時のプロキシ適用（#34509）、認証リフレッシュ時のプロキシ経路適用（#34655）、LM Studio 接続のプロキシ経由化（#34678）、exec-server HTTP 通信のプロキシ適用（#35023）、WebSocket 通信のプロキシ経由化（#35056）、MCP 認可のプロキシ対応（#35239）など、広範な通信経路で対応が行われています。これにより、Windows サンドボックス内での Guardian セッションにおけるプロキシ設定の保持（#35036）も実現されています。

## 実用的な活用ポイント

### 日常の開発ワークフローへの影響

本リリースの機能により、以下のような実務上の改善が期待できます：

**マルチタスクの効率化**  
名前付きセッションとピン留め機能により、「本番障害対応」「新機能開発」「ドキュメント整備」といった複数のタスクを同時進行しやすくなります。サイド会話の保持機能により、メインのコードレビュー中にちょっとしたドキュメント確認や調査を行い、再びレビューに戻る、といった作業フローがスムーズになります。

**企業環境での導入障壁の低減**  
プロキシ設定の統一的適用により、企業ネットワーク内での Codex CLI の利用がより安定します。これまでプロキシ未対応が原因で導入を見送っていた組織でも、本バージョン以降は全ての機能が一貫してプロキシ経由で動作するため、安心して導入できます。

**プラグインエコシステムの拡張**  
Agent Plugins マニフェストのサポート（#35105）、ワークスペースプラグインの公開機能（#35254）、Amazon Bedrock や Claude Code 向けマーケットプレイスの追加（#34931, #34979）により、組織内で独自のプラグインを共有したり、外部マーケットプレイスから追加機能を取得したりすることが容易になります。

### SRE/インフラエンジニアの視点での活用シーン

**リモート実行環境との連携強化**  
WebSocket を使ったリモート Code Mode ホストへの接続（#35078, #35098）により、ローカル端末から本番環境や検証環境上の Codex 機能を直接利用できます。インフラエンジニアが踏み台サーバー経由で本番調査を行う際にも、Codex のコード補完や解析機能を活用できるようになります。

**スキルベースの自動化**  
executor が提供するスキルの自動検出（#35184）と、選択されたスキルのリソース読み取り機能（#35198）により、インフラ運用タスクをスキルとして定義し、Codex CLI から動的に呼び出すワークフローが実現できます。例えば、監視ダッシュボードの確認やログ解析といった定型業務をスキル化し、自然言語ベースで実行することが可能です。

**MCP 接続の安定性向上**  
MCP サーバーの接続維持と再接続処理の改善（#34952, #34957, #35028, #35144, #35146, #35151）により、長時間稼働する運用セッションでも MCP ベースのツールや外部サービス連携が安定して利用できるようになります。認証や設定変更時にも健全な接続は維持されたまま、必要な接続のみが再確立されるため、運用中の中断が最小限に抑えられます。

## まとめ

rust-v0.146.0 は、Codex CLI の実用性と堅牢性を大きく向上させるリリースです。セッション管理の柔軟性向上により、複数タスクを並行して扱う開発者の生産性が向上し、プロキシ設定の統一的適用により企業環境での安定稼働が実現されました。スレッドフォーク機能やリモート Code Mode ホスト接続、executor スキルの検出とリソース読み取りといった新機能は、より高度なワークフローや自動化シナリオへの道を開きます。

MCP 接続の維持・再接続ロジックの改善や、ターミナル応答性の向上といった細かな改善も多数含まれており、日常使いでのストレス軽減につながります。プラグインエコシステムの拡張により、組織やコミュニティが独自の機能を追加・共有しやすくなった点も見逃せません。

SRE やインフラエンジニアにとっては、リモート環境での安定した Codex 利用、スキルベースの運用自動化、長時間稼働セッションでの MCP ツール活用といった実務上のメリットが大きいリリースと言えます。今後のアップデートでさらなる改善が期待される中、本バージョンは現時点での Codex CLI の完成度を大きく引き上げる重要なマイルストーンとなっています。
