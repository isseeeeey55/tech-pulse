# Claude Code v2.1.128 リリース解説

## はじめに

2026年5月6日、Claude Code v2.1.128 がリリースされました。本バージョンでは、MCP（Model Context Protocol）サーバーの接続管理改善、プラグインアーキテクチャの強化、Git ワークフロー関連のバグ修正など、開発体験の向上に焦点を当てた複数のアップデートが実施されています。

主な変更点は以下の通りです：

- **MCP サーバー接続管理の改善**：ツール情報の重複表示を削減し、接続状態の可視性を向上
- **プラグインアーキテクチャの強化**：.zip形式のプラグイン配布に対応
- **EnterWorktree の不具合修正**：未プッシュコミットの喪失問題を解決
- **OTEL環境変数の分離**：サブプロセスの計測を独立化し、observability 基盤を強化
- **複数のバグ修正**：安定性と信頼性の向上

本記事では、これらのアップデートの中から特に重要な変更を技術的に深掘りし、実務への影響と活用ポイントを解説します。

## 注目アップデート深掘り

### MCP サーバー接続管理の改善とツール情報重複削減

今回のリリースで最も注目すべきは、MCP サーバーの接続管理機構の改善です。MCP は Claude Code が外部ツールやデータソースと連携するためのプロトコルですが、従来は複数の MCP サーバーが同じツールを提供している場合や、接続の再確立時にツール情報が重複して表示される問題がありました。

> **Note:** MCP（Model Context Protocol）は、Claude Code が外部システムと連携するための標準プロトコルです。MCP サーバーは特定のツール群（APIクライアント、データベース接続、ファイルシステムアクセスなど）を提供します。

本アップデートでは、この重複表示を削減する機構が導入されました。これにより、Claude に利用可能なツールを提示する際の情報がよりクリーンになり、コンテキストウィンドウの効率的な利用が可能になります。また、接続状態の管理も改善されており、MCP サーバーとの通信エラーや切断時の挙動がより予測可能になっています。

この変更が重要な理由は、MCP を活用した開発ワークフローの信頼性に直結するためです。特に複数の MCP サーバーを組み合わせて使用している環境では、ツール情報の重複がノイズとなり、Claude の応答品質に影響を与える可能性がありました。接続管理の改善により、MCP サーバーの再起動やネットワーク障害からの復旧時にも、より安定した動作が期待できます。

実務的には、開発環境で複数の MCP サーバー（例：データベース接続用、クラウドAPI用、社内ツール用など）を併用しているチームにとって、この改善は日常的な開発体験の向上につながるでしょう。

### EnterWorktree での未プッシュコミット喪失問題の修正

Git worktree を活用した並行作業フローにおいて、重大なバグが修正されました。`EnterWorktree` 機能の実行時に未プッシュのコミットが喪失する可能性があった問題が解決されています。

> **Note:** `EnterWorktree` は、Claude Code が Git worktree を切り替える際に使用する内部機能です。複数のブランチで並行作業を行う際に、別の worktree に安全に移動できるようにします。

この問題は、特にフィーチャーブランチで作業中にレビュー対応や緊急の修正対応で別のブランチに切り替える必要がある場合に影響がありました。従来は、ローカルコミットがリモートにプッシュされていない状態で worktree を切り替えると、そのコミット履歴が失われるリスクがあったのです。

本修正により、未プッシュコミットの存在を検出し、適切に保護する機構が強化されました。これにより、開発者は安心して worktree ベースの並行作業フローを利用できるようになります。特に、複数の作業を同時進行させるマルチタスクな開発スタイルや、緊急対応が頻繁に発生する運用チームにとって、この修正は作業の安全性を大きく向上させます。

SRE やインフラエンジニアの観点では、本番環境の緊急対応中に別の worktree で検証作業を並行して行うといったシーンで、コミット履歴の喪失リスクが軽減されることは重要な改善です。作業の中断と再開が頻繁に発生する環境において、データロスのリスクを減らすことは、チーム全体の生産性と心理的安全性の向上に寄与します。

### OTEL 環境変数の分離によるサブプロセス計測の独立化

observability 基盤の強化として、OpenTelemetry（OTEL）関連の環境変数の分離が実施されました。これにより、Claude Code のメインプロセスと、そこから起動されるサブプロセス（MCP サーバー、ビルドツール、テストランナーなど）の計測が独立して管理できるようになります。

従来は、Claude Code の OTEL 設定が子プロセスにも継承されるため、意図しないトレースデータの混入や、サブプロセスの計測データが親プロセスのトレースに紛れ込む問題がありました。本変更により、サブプロセスは独自の OTEL 設定を持つか、計測を無効化できるようになり、より正確な observability データの収集が可能になります。

この改善は、分散トレーシングを活用してパフォーマンス分析を行っているチームにとって特に有益です。Claude Code を通じて実行されるビルドプロセスやテスト実行の計測を、Claude Code 本体の動作とは分離して分析できるようになるため、ボトルネックの特定精度が向上します。

SRE の視点では、本番環境やステージング環境で動作する CI/CD パイプラインの中で Claude Code を利用している場合、このトレースの分離により、システム全体の observability が向上します。各コンポーネントのパフォーマンス特性を独立して把握できることは、効率的なトラブルシューティングとキャパシティプランニングに不可欠です。

## 実用的な活用ポイント

本リリースの変更は、日常的な開発ワークフローに以下のような影響をもたらします。

**MCP サーバー利用の最適化**：複数の MCP サーバーを使用している場合は、今回の接続管理改善により、より安定した動作が期待できます。接続エラーが発生した際の挙動も改善されているため、MCP サーバーの再起動やネットワーク障害からの復旧がスムーズになります。定期的に MCP サーバーの接続状態を確認し、不要な重複がないかチェックすることで、Claude のパフォーマンスを最大化できます。

**Git worktree の安全な活用**：`EnterWorktree` の修正により、並行作業フローが安全になりました。複数のフィーチャーブランチを同時に扱う場合や、緊急対応で作業を中断する必要がある場合でも、未プッシュコミットの喪失を心配する必要がなくなります。ただし、定期的なプッシュやブランチの整理といった基本的な Git 運用のベストプラクティスは引き続き重要です。

**プラグイン配布の効率化**：.zip 形式のプラグイン対応により、チーム内でカスタムプラグインを配布する際の利便性が向上しました。社内ツールとの統合や、特定のワークフローに最適化されたプラグインをパッケージ化して共有する運用が容易になります。

**observability の強化**：OTEL 環境変数の分離により、Claude Code を含む開発ツールチェーン全体の計測精度が向上します。パフォーマンス問題の調査時には、プロセスごとのトレースを独立して分析できるため、より迅速な問題特定が可能です。

SRE やインフラエンジニアにとっては、特に OTEL の改善と Git worktree の修正が実務上の安全性向上に直結します。緊急対応時の作業の安全性が向上し、システム全体の observability が強化されることで、より効率的な運用が可能になるでしょう。

## まとめ

Claude Code v2.1.128 は、MCP の接続管理改善、プラグインアーキテクチャの強化、Git ワークフローの安全性向上など、開発体験の質を高める変更が中心となっています。特に、MCP サーバーとの統合を活用している環境や、Git worktree を用いた並行作業フローを採用しているチームにとって、本リリースは実務上の信頼性と効率性を大きく向上させるでしょう。

また、OTEL 環境変数の分離による observability 基盤の強化は、システム全体のパフォーマンス分析とトラブルシューティングの精度向上に寄与します。これらの改善は、Claude Code を中心とした開発ツールチェーンの成熟度を示すものであり、エンタープライズ環境での利用においても重要な前進と言えます。

今回のリリースには複数のバグ修正も含まれており、全体として安定性と信頼性が向上しています。日常的な開発ワークフローにおいて、より安心して Claude Code を活用できる基盤が整ったと評価できるでしょう。
