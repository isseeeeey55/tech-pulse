# 直近のAWSアップデート解説 - バックアップ、EC2予約、AI強化を中心に

## はじめに

今回は、直近で発表された6件のAWSアップデートを紹介します。AWS Backup のロジカルエアギャップ機能が FSx for NetApp ONTAP に対応し、ランサムウェア対策が強化されました。また、EC2 の Future-dated Capacity Reservations に開始日の後延ばし機能が追加され、柔軟な計画変更が可能になっています。さらに、Claude Sonnet 5.5 が AWS および GovCloud で利用可能になり、コーディングと知識業務の性能が大幅に向上しました。Amazon Rekognition Face Liveness はフィードバックコード機能を追加し、認証失敗時の具体的な改善指示が可能になっています。Amazon Corretto の複数バージョンも最新のタイムゾーンデータを含むパッチ更新がリリースされました。

本記事では、これらのアップデートの中から特に注目すべき機能を深掘りし、SRE視点での活用ポイントを解説します。

## 注目アップデート深掘り

### AWS Backup のロジカルエアギャップ機能が FSx for NetApp ONTAP に対応

#### なぜこのアップデートが重要なのか

近年、ランサムウェア攻撃の巧妙化により、バックアップデータそのものが攻撃対象となるケースが増加しています。攻撃者はバックアップを暗号化または削除することで、復旧を困難にし、身代金要求の圧力を高めます。このような脅威に対抗するため、バックアップデータを物理的または論理的に隔離する「エアギャップ」戦略が重要視されています。

AWS Backup のロジカルエアギャップ機能は、バックアップデータをデフォルトでロックされた不変の状態で保存し、攻撃者や悪意のある管理者からも改ざん・削除できないようにします。今回、この強力な保護機能が Amazon FSx for NetApp ONTAP に対応したことで、オンプレミスの NetApp 環境からクラウドに移行した組織や、ハイブリッド環境を運用する組織も、同等のセキュリティレベルを維持できるようになりました。

#### ロジカルエアギャップの仕組みと設定

ロジカルエアギャップ機能では、バックアップを「ロジカルエアギャップコンテナ」と呼ばれる特別な保管場所に格納します。このコンテナは、通常のバックアップボールトとは異なり、以下の特性を持ちます：

- **デフォルトロック**: 作成されたバックアップは自動的にロックされ、削除や変更ができません
- **暗号化による隔離**: AWS所有キーまたはカスタマー管理キーによる暗号化が必須で、データは論理的に隔離されます
- **クロスアカウント・クロスリージョン対応**: 同じアカウント内だけでなく、複数のアカウントやリージョンに跨ってバックアップを保存可能です

設定は AWS Backup コンソール、CLI、SDK から実行できます。バックアッププラン内で、ロジカルエアギャップコンテナを主要なターゲットまたはコピー先として指定します。従来の標準コンテナと比較すると、ロジカルエアギャップコンテナは追加の保護レイヤーを提供する代わりに、復旧時の手順がやや複雑になる可能性があります。しかし、直接復旧ジョブをサポートしているため、バックアップコピーのオーバーヘッドを排除し、効率的な復旧が可能です。

#### AWS RAM とマルチパーティ承認による追加保護

AWS Resource Access Manager（RAM）を使用すると、ロジカルエアギャップコンテナを他のアカウントと共有できます。これにより、複数の部門やチームが同じバックアップ基盤を安全に利用できます。さらに、マルチパーティ承認機能を活用すれば、アカウント侵害時でも単独でのアクセスを防止できます。

例えば、本番環境のバックアップを別のセキュリティ管理用アカウントに保存し、復旧時には複数の承認者（システム管理者とセキュリティ担当者）の同意を必要とする設定が可能です。これにより、内部不正やアカウント乗っ取りのリスクを大幅に低減できます。

#### 既存のバックアップ戦略との比較

標準のバックアップボールトは、日常的なデータ保護とコスト効率のバランスが取れており、定期的なバックアップ・復旧が頻繁に発生する環境に適しています。一方、ロジカルエアギャップコンテナは、ランサムウェア対策やコンプライアンス要件が厳格な環境、特に金融・医療業界でのディザスタリカバリや長期保存が必要な場合に最適です。

コスト面では、ロジカルエアギャップコンテナは暗号化と隔離の追加機能により、標準コンテナと比較してやや高コストになる可能性がありますが、データ損失時の復旧コストや業務停止による損失を考慮すれば、十分に投資対効果が見込めます。

### EC2 Future-dated Capacity Reservations の開始日後延ばし機能

#### 柔軟な計画変更がもたらす価値

Amazon EC2 の Future-dated Capacity Reservations（先行予約機能）は、最大120日先までのキャパシティを事前に確保できる機能です。大規模なイベント、プロジェクトローンチ、季節的な需要増加に備えて、確実にインスタンスを起動できる環境を準備できます。

しかし、プロジェクトのスケジュールは常に流動的です。開発の遅れ、ビジネス要件の変更、外部要因による計画見直しなど、予約した開始日を変更したいケースは実際の運用では頻繁に発生します。今回追加された開始日の後延ばし機能により、予約をキャンセルして再予約する手間を省き、柔軟にスケジュールを調整できるようになりました。

#### 開始日変更時のコミットメントと見積もり

開始日を後延ばしする際には、新しい開始日と必要なコミットメント期間を示す見積もりが提示されます。このコミットメント期間は、後延ばしのタイミングによって変動する可能性があります。例えば、開始日を大幅に遅延させる場合、コミットメント期間が延長されることが考えられます。

見積もりを確認し、承認することで予約が更新されます。このプロセスにより、予期しないコスト変動や契約条件の変更を事前に把握でき、透明性の高い運用が可能になります。

#### 従来の Capacity Reservations との使い分け

EC2 には、通常の Capacity Reservations（即座に開始）と Future-dated Capacity Reservations（先行予約）の2種類があります。通常の Capacity Reservations は、今すぐキャパシティが必要な場合や、短期間の利用に適しています。一方、Future-dated Capacity Reservations は、数週間〜数ヶ月先の計画的な利用に最適です。

今回の開始日後延ばし機能により、Future-dated Capacity Reservations は「計画が流動的だが、確実にキャパシティを確保したい」というシナリオにも対応できるようになりました。特に、マルチステージのデプロイメント計画や、段階的な移行プロジェクトにおいて、各フェーズの開始日が不確定な場合に有効です。

#### 利用可能性と地域差

この機能は既存の全 Future-dated Capacity Reservation ユーザーが利用可能ですが、地域によって利用可能性が異なる点に注意が必要です。グローバル展開を行う場合は、各リージョンでの機能サポート状況を事前に確認し、リージョンごとの計画を立てることが推奨されます。

### Amazon Rekognition Face Liveness のフィードバックコード機能

#### 認証失敗時のユーザー体験向上

顔認証の生体認証チェック（Face Liveness）は、本人確認やアクセス制御において重要な役割を果たしますが、認証に失敗した際にユーザーが「なぜ失敗したのか」を理解できないと、再試行の成功率が低下し、ユーザー体験が大幅に悪化します。

今回追加されたフィードバックコード機能により、GetFaceLivenessSessionResults API のレスポンスに、スコアが低かった具体的な理由が含まれるようになりました。照明不足、顔の遮蔽、目を閉じている、動画品質が低いなど、具体的な原因を特定できます。

#### フィードバックコードの活用方法

フィードバックコードを受け取ったアプリケーションは、ユーザーに対して具体的な改善指示を提示できます。例えば：

- **照明不足**: 「もう少し明るい場所で撮影してください」
- **顔の遮蔽**: 「マスクや帽子を外してください」
- **目を閉じている**: 「カメラを見つめて目を開けてください」
- **動画品質が低い**: 「ネットワーク接続を確認し、カメラのレンズを拭いてください」

さらに、1回の再試行で複数の問題をまとめて解決できるため、ユーザーは複数のフィードバックを同時に確認し、一度に対処できます。これにより、再試行の成功率が大幅に向上し、ユーザーの離脱率を低減できます。

#### 実装とベストプラクティス

GetFaceLivenessSessionResults API を呼び出す際、レスポンスにフィードバックコードが含まれているかを確認し、アプリケーション側で適切なメッセージを表示します。複数のフィードバックコードが同時に返却されることもあるため、優先度を付けてユーザーに提示することが推奨されます。

例えば、「照明不足」と「動画品質が低い」が同時に返却された場合、まず照明を改善することで動画品質も向上する可能性があるため、照明不足を優先的に表示するといった工夫が考えられます。

アクセシビリティの観点でも、スクリーンリーダー対応や音声ガイダンスと併用することで、視覚障害や操作困難なユーザーにも対応できます。

## SRE視点での活用ポイント

### バックアップとディザスタリカバリの強化

AWS Backup のロジカルエアギャップ機能は、SREにとってランサムウェア対策とディザスタリカバリ計画の両面で重要なツールです。Terraform で管理しているインフラがあれば、バックアッププランにロジカルエアギャップコンテナを組み込むことで、Infrastructure as Code（IaC）の一環として自動化できます。

マルチアカウント環境では、AWS RAM を活用して本番環境とバックアップ管理アカウントを分離し、復旧時のアクセス制御を厳格化することで、内部不正や誤操作のリスクを低減できます。CloudWatch アラームと組み合わせて、バックアップの成功・失敗を監視し、異常が検出された際には即座に対応できる体制を整えることも重要です。

導入時には、既存のバックアップ戦略との整合性、コスト増加の許容範囲、復旧手順の複雑化による運用負荷を評価する必要があります。特に、復旧テストを定期的に実施し、ロジカルエアギャップコンテナからの復旧フローを検証することで、実際の障害時にスムーズに対応できるようにしておくことが推奨されます。

### キャパシティ管理の柔軟性向上

EC2 Future-dated Capacity Reservations の開始日後延ばし機能は、大規模なシステム移行やイベント対応において、計画の変更に柔軟に対応できるようになります。SREがキャパシティプランニングを行う際、不確実性が高い要素（開発遅延、ビジネス要件変更など）を考慮しつつ、確実にリソースを確保できる手段として活用できます。

CloudWatch メトリクスやカスタムメトリクスで需要予測を行い、予約の開始日を動的に調整することで、コスト最適化と可用性の両立が可能です。Terraform や AWS CLI で予約を管理している場合、開始日変更のワークフローを自動化し、承認プロセスを組み込むことで、運用の効率化と透明性の向上が期待できます。

ただし、コミットメント期間の変動に注意し、見積もりを必ず確認してから承認することが重要です。また、地域によって利用可能性が異なるため、グローバル展開時には各リージョンのサポート状況を把握し、代替手段を用意しておくことも必要です。

### 認証システムの信頼性とUX改善

Amazon Rekognition Face Liveness のフィードバックコード機能は、本人確認フローの信頼性とユーザー体験の両方を改善します。SREが運用する認証システムにおいて、失敗率の高い認証プロセスはユーザーの離脱やサポートコストの増加につながります。

フィードバックコードを活用することで、ユーザー自身が問題を解決できるようになり、サポートへの問い合わせを削減できます。また、フィードバックコードの統計データを収集・分析することで、認証失敗の傾向を把握し、アプリケーション側の改善（UIの調整、照明ガイドの追加など）やインフラ側の最適化（ネットワーク品質の向上など）につなげることができます。

導入時には、GetFaceLivenessSessionResults API の呼び出し頻度やレスポンス時間を監視し、パフォーマンスへの影響を評価することが推奨されます。また、障害対応のランブックに、フィードバックコードのエラーハンドリングとユーザー向けメッセージのマッピングを組み込んでおくと、運用時のトラブルシューティングがスムーズになります。

## まとめ

今回紹介した6件のアップデートは、セキュリティ、柔軟性、AI活用、信頼性という4つの軸で AWS のサービスを強化するものでした。

AWS Backup のロジカルエアギャップ機能は、ランサムウェアの脅威が増大する中で、バックアップデータの保護を一層強固にします。EC2 の Future-dated Capacity Reservations の開始日後延ばし機能は、計画の変更に柔軟に対応でき、コスト最適化と可用性の両立を支援します。Claude Sonnet 5.5 の AWS および GovCloud での提供は、AI駆動の開発と業務効率化を加速させ、特に政府機関や規制の厳しい業界でも安全に活用できる環境を提供します。Amazon Rekognition Face Liveness のフィードバックコード機能は、認証システムのユーザー体験を大幅に改善し、運用負荷の軽減にも貢献します。Amazon Corretto のパッチ更新は、タイムゾーンデータの最新化により、グローバルアプリケーションの時間精度を確保します。

これらのアップデートを活用することで、SREはシステムの信頼性向上、運用効率化、コスト最適化を実現できます。今後も AWS の継続的な機能強化に注目し、積極的に取り入れていくことが、競争力のあるインフラ運用につながるでしょう。
