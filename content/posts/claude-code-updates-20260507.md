# Claude Code v2.1.129〜v2.1.132 リリース情報

## はじめに

2026年5月7日、Claude Codeの3つのバージョン（v2.1.129、v2.1.131、v2.1.132）が相次いでリリースされました。これらのリリースは、プラットフォーム全体の安定性向上とクロスプラットフォーム対応強化に焦点を当てた内容となっています。

v2.1.129ではプラグイン管理の強化とターミナル互換性の向上、v2.1.131ではWindows環境における重大な起動問題の修正、v2.1.132ではセッション管理とマルチバイト文字対応の改善が行われました。特に、プラグインマニフェストでの実験的機能の明示的宣言要求、VS Code拡張機能のWindows起動問題の解決、SSHセッション復旧の信頼性向上など、日常的な開発ワークフローに直結する改善が多数含まれています。

## 注目アップデート深掘り

### プラグインマニフェストにおける実験的機能の明示的宣言（v2.1.129）

今回のリリースで最も重要な変更の一つが、プラグイン管理の強化です。v2.1.129から、プラグインマニフェストで実験的機能を明示的に宣言することが必要になりました。この変更は、プラグインエコシステムの成熟と安定性向上を目指したものです。

従来は実験的機能の利用が暗黙的に許可されていましたが、これにより互換性の問題や予期しない動作が発生するリスクがありました。新しい仕組みでは、プラグイン開発者が使用する実験的機能を明示的にマニフェストに記載する必要があり、ユーザーはどのプラグインがどの実験的機能に依存しているかを事前に把握できるようになります。

この変更により、プラグインのメンテナンス性が向上し、Claude Codeのコアアップデートによる破壊的変更の影響範囲を事前に特定できるようになります。プラグイン開発者にとっては、依存関係の明示化により、将来的なAPIの変更に備えた計画的な対応が可能になります。また、エンタープライズ環境においては、実験的機能の使用状況を監査しやすくなるという副次的なメリットもあります。

> **Note:** プラグインとは、Claude Codeの機能を拡張するサードパーティ製のモジュールです。マニフェストファイルに機能要件や依存関係を記述します。

### Windows環境でのVS Code拡張機能起動問題の修正（v2.1.131）

v2.1.131では、Windows環境においてVS Code拡張機能が起動しない重大な問題が解決されました。この問題の原因は、bundled SDKのビルドパス処理において、`createRequire`ポリフィルがハードコードされたパスを使用していたことにありました。

具体的には、Node.jsの`require`関数をエミュレートする際に、WindowsとUnix系OSのパス区切り文字の違い（バックスラッシュ vs スラッシュ）が適切に処理されていませんでした。これにより、Windows環境では拡張機能の初期化段階でモジュール解決に失敗し、起動が完全にブロックされる状態になっていました。

今回の修正により、パス処理がプラットフォームに依存しない形に改善され、Windows、macOS、Linuxの全環境で一貫した動作が保証されるようになりました。この修正は、Claude CodeをWindows環境で利用するユーザーにとって必須のアップデートです。特に、企業環境でWindowsワークステーションを使用している開発チームでは、この修正により初めて安定したVS Code統合が利用可能になります。

クロスプラットフォーム開発において、このようなパス処理の問題は見落とされがちですが、ユーザー体験に直結する重要な要素です。今回の修正は、Claude CodeのWindows対応の成熟度を示す重要なマイルストーンと言えるでしょう。

## 実用的な活用ポイント

### セッション管理とターミナルの安定性向上

v2.1.132で実装されたSSHセッション復旧の信頼性向上は、リモート開発を行うエンジニアにとって特に重要です。ネットワーク接続が不安定な環境や、長時間のセッションを維持する必要があるシナリオにおいて、予期しないセッション切断からの復旧がよりスムーズになります。また、グレースフルシャットダウンの修正により、作業中のコンテキストが適切に保存され、再起動後の作業再開が容易になりました。

ターミナルUI関連では、絵文字やマルチバイト文字（日本語を含む）の表示バグが修正されたことで、国際化された開発環境での使用感が大きく改善されました。コミットメッセージやログ出力に絵文字を使用するチームや、日本語のファイル名・コメントを含むプロジェクトで、文字化けや表示崩れが解消されます。

### パッケージマネージャー対応とアップデート体験

v2.1.129でHomebrewとWinGetの自動更新機能が追加されたことにより、各プラットフォームのネイティブなパッケージ管理ツールを通じた更新が可能になりました。macOSユーザーは`$ brew upgrade claude-code`、Windowsユーザーは`$ winget upgrade AnthropicPBC.ClaudeCode`といった慣れ親しんだコマンドでアップデートできます。これにより、CI/CD環境やインフラストラクチャのコード管理においても、バージョン管理がより統一的に行えるようになります。

Ctrl+R履歴検索の改善も地味ながら生産性に直結する改善です。ターミナルでの作業履歴を素早く呼び出せることで、繰り返し実行するコマンドの入力時間を削減できます。SREやインフラエンジニアが頻繁に実行する診断コマンドやデプロイスクリプトの呼び出しが、より効率的になるでしょう。

## まとめ

今回の3つのリリースは、派手な新機能追加よりも、既存機能の安定性向上とクロスプラットフォーム対応の成熟に焦点を当てた内容となっています。特にWindows環境での起動問題の解決は、プラットフォームの包括性を重視する姿勢の表れと言えます。

プラグインエコシステムの管理強化、マルチバイト文字対応、セッション復旧の改善など、日常的な開発作業における細かな課題に対処することで、全体的なユーザー体験が着実に向上しています。これらの改善は、Claude Codeが実験的なツールから本格的な開発インフラストラクチャへと進化している過程を示しています。

特にエンタープライズ環境や国際的なチームで使用する場合、これらの安定性向上と互換性改善は重要な要素です。パッケージマネージャー対応の追加により、組織全体でのバージョン管理やデプロイメント戦略もより洗練されたものになるでしょう。今後も、このような地道な改善の積み重ねが、Claude Codeの実用性をさらに高めていくことが期待されます。
