## はじめに

2026年9月11日、OpenAI Codex の Python SDK バージョン 0.154.0 がリリースされました。本リリースには、マッチングする `openai-codex-cli-bin==0.154.0` ランタイムが含まれています。Python 3.10 以降が必要です。

今回のアップデートでは、推論制御機能の拡張、外部メッセージ統合の強化、ターン管理機能の改善という3つの大きな柱があります。特に `max` および `ultra` という新しい推論努力レベルの追加、`ExternalMessage` による外部コンテンツの統合機能、`include_turns` や `turn_service_tier` といったターン制御オプションの追加が目玉となっています。また、プロトコルモデルの刷新とイベント処理の改善により、より複雑なワークフローへの対応が進化しました。

一方で、`HookMetadata` の構造変更や通知ペイロードの型定義変更など、破壊的変更も含まれているため、アップグレード時には注意が必要です。

## 注目アップデート深掘り

### 1. 推論努力レベルに `max` と `ultra` を追加

今回のリリースで、推論努力レベルに `max` と `ultra` という2つの新しい値が追加されました（[#39662](https://github.com/openai/codex/pull/39662)）。

この機能拡張は、より高度な推論が必要なタスクに対して、モデルがより多くの計算リソースを使用できるようにするものです。従来の推論努力レベルに加えて、これらの新しいオプションを使用することで、複雑な問題解決やコード生成において、より精度の高い結果を得られる可能性があります。

具体的な使用方法や設定詳細については、リリースノートには明記されていませんが、推論の質とコストのトレードオフを考慮しながら、プロジェクトの要件に応じて適切なレベルを選択できるようになりました。特に、従来のデフォルト設定では十分な精度が得られなかったケースや、クリティカルな判断を要するコード生成タスクにおいて、これらの新しいオプションが有効となるでしょう。

### 2. `ExternalMessage` による外部コンテンツ統合の強化

本リリースでは、同期・非同期の `run()` および `turn()` 呼び出しに `ExternalMessage` が追加されました（[#44086](https://github.com/openai/codex/pull/44086)）。

この機能により、外部コンテンツがターンを開始したり、アクティブな通常ターンに参加したりすることが可能になりました。重要な点として、外部コンテンツはツールレベルの権限で動作し、ユーザー承認を付与するものではありません。また、各コンシューマーは独立したイベントストリームを受信します。

この変更により、複数の外部システムやツールからのメッセージを Codex CLI のワークフローに統合する際の柔軟性が大幅に向上しました。例えば、CI/CD パイプラインからの通知、モニタリングシステムからのアラート、あるいは他の自動化ツールからの情報を、進行中のコーディングセッションに適切に組み込むことができます。

イベントストリームが独立している点は、複数の外部ソースから同時にメッセージが流入する場合でも、それぞれのコンテキストを保持しながら処理できることを意味します。ただし、カスタムの `codex_bin` オーバーライドを使用している場合は、CLI 0.151.0 以降が必要となる点に注意が必要です。

### 3. ターン管理機能の細粒度制御

resume/fork 時の `include_turns` オプション、新規開始ターン用の `turn_service_tier`、そして `source` メタデータが追加されました（[#44084](https://github.com/openai/codex/pull/44084)）。

リリースノートによれば、履歴選択は返されるレスポンスを変更するものであり、モデルコンテキストそのものを変更するわけではありません。これらのオプションが省略された場合、既存のデフォルト動作が保持されます。

`include_turns` オプションは、セッションを再開またはフォークする際に、どのターンの履歴を含めるかを制御します。これにより、長時間のセッションにおいて必要な履歴のみを選択的に読み込むことができ、効率的なコンテキスト管理が可能になります。

`turn_service_tier` は、新しく開始される個別のターンに対してサービスティアを指定できる機能です。これにより、特定のターンだけより高性能なリソースを使用するといった、きめ細かなリソース配分が実現できます。

`source` メタデータの追加により、各ターンの起源を追跡しやすくなり、デバッグやログ分析の際に有用な情報を提供します。

## 実用的な活用ポイント

### 日常の開発ワークフローへの影響

新しい推論努力レベル `max` と `ultra` は、コードレビューや複雑なリファクタリング作業において、より精度の高い提案を得たい場合に有効です。通常の開発では従来のレベルを使用し、クリティカルな判断が必要な場面でのみこれらを使用することで、コストと品質のバランスを取ることができます。

`ExternalMessage` 機能は、CI/CD パイプラインとの統合や、モニタリングツールからのアラートをコーディングセッションに取り込む際に特に有用です。SRE やインフラエンジニアの視点では、本番環境のメトリクスやログ情報を Codex CLI のセッションに直接フィードすることで、問題のトラブルシューティングやパフォーマンス改善のための提案を、リアルタイムのコンテキストとともに得られるようになります。

### マイグレーション時の注意点

アップグレード時には、以下のマイグレーション対応が必要です：

- **`HookMetadata` の構造変更**: ハンドラーが `.root` にラップされるようになりました。`hook.command` のようなアクセスを `hook.root.command` に変更し、ハンドラー固有のフィールドを読む前に `hook.root.handler_type` をチェックする必要があります。

- **通知ペイロードの型定義**: これまで不明だった一部の通知に、型付きペイロードが追加されました。`.params` の代わりに名前付きフィールドを読み取るようにコードを更新してください。不明または無効なペイロードは引き続き `UnknownNotification` を使用します。

- **ターンハンドルのイベント動作**: 手動で構築したり、途中参加したりするターンハンドルは、アタッチポイントからイベントを受信します。以前の出力は再生されないため、収集された結果が部分的になる可能性があります。完了後にアタッチすると `TransportClosedError` が発生する可能性があります。保存された履歴には `thread.read(include_turns=True)` を使用してください。なお、`thread.turn(...)` によって直接返されるハンドルは、リクエスト送信時点からのイベントを保持します。

### すぐに試せる Tips

インストールは以下のコマンドで行えます：

```bash
$ pip install --upgrade openai-codex==0.154.0
```

カスタムの `codex_bin` オーバーライドを使用している環境では、`ExternalMessage` および新しい履歴・ターンごとのオプションを利用するために CLI 0.151.0 以降が必要です。既存の環境を確認し、必要に応じて CLI もアップグレードしてください。

## まとめ

Python SDK 0.154.0 は、推論制御の柔軟性向上、外部システム統合の強化、ターン管理の細粒度化という3つの軸で Codex CLI の機能を大きく拡張するリリースとなりました。

`max` と `ultra` の推論努力レベル追加により、タスクの重要度に応じた推論品質の調整が可能になり、`ExternalMessage` 機能は外部ツールやシステムとのシームレスな統合を実現します。さらに、ターン管理オプションの追加により、長時間セッションや複雑なワークフローにおける柔軟な制御が可能になりました。

一方で、`HookMetadata` の構造変更や通知ペイロードの型定義変更など、いくつかの破壊的変更も含まれています。アップグレードの際には、マイグレーションガイドに従って既存コードを適切に更新する必要があります。特に、ターンハンドルのイベント動作変更は、イベント処理ロジックに影響を与える可能性があるため、十分なテストを実施することをお勧めします。

全体として、本リリースは Codex CLI をより強力で柔軟なツールへと進化させるものであり、特に複雑な開発ワークフローや外部システムとの統合を必要とするチームにとって、大きな価値をもたらすアップデートと言えるでしょう。
