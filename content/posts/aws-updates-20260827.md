## 注目アップデート深掘り

### AWS Backup が DocumentDB のクロスリージョンバックアップとエアギャップ機能を拡張

AWS Backup は Amazon DocumentDB のクロスリージョンバックアップコピーと論理的にエアギャップされたコンテナのサポートを、9つの新しいリージョン（香港、ジャカルタ、メルボルン、大阪、スペイン、ストックホルム、チューリッヒ、ケープタウン、テルアビブ）で開始しました。このアップデートは、グローバル企業やマルチリージョン展開を進める組織にとって、災害復旧（DR）戦略とランサムウェア対策の両面で重要な意味を持ちます。

**クロスリージョンバックアップコピーの意義**

DocumentDB のバックアップをリージョン間でコピーできる機能により、プライマリリージョンで大規模障害が発生した場合でも、別リージョンでデータを迅速に復旧できるようになります。バックアッププランを使用すれば定期的な自動コピーを、オンデマンドコピージョブを使用すれば特定のタイミングでの手動コピーを実行できます。これにより、RPO（目標復旧時点）とRTO（目標復旧時間）をより厳格にコントロールできます。

**論理的にエアギャップされたコンテナの保護メカニズム**

論理的にエアギャップされたコンテナは、バックアップを不変（immutable）かつ隔離された状態で保存します。デフォルトでロックされており、AWS 所有キーまたはカスタマーマネージドキーで暗号化されます。重要なのは、AWS Resource Access Manager（RAM）を使用してコンテナを共有し、マルチパーティ承認（複数の承認者による認証）を設定できる点です。これにより、単一のアカウントが侵害されても、攻撃者がバックアップを削除・改ざんできないようにする多層防御が実現します。

**実装検討のポイント**

新たにサポートされたリージョンで DocumentDB を運用している場合、まず既存のバックアップ戦略を見直し、クロスリージョンコピーの必要性を評価すべきです。特に、以下の観点から検討すると良いでしょう：

- **コスト**: クロスリージョン転送コストとストレージコストのトレードオフ
- **コンプライアンス**: データレジデンシー要件と規制対応
- **復旧速度**: リージョン間の距離とネットワークレイテンシーが復旧時間に与える影響

従来は手動スクリプトや Lambda 関数で DocumentDB のクロスリージョンバックアップを管理していた環境では、AWS Backup の統合管理機能に移行することで運用負荷を大幅に削減できます。

### Mountpoint for Amazon S3 のメモリ制御機能による共存環境の最適化

Mountpoint for Amazon S3 に追加されたメモリ使用量制御機能は、メモリ集約的なアプリケーション（機械学習トレーニングや分析ワークロード）と S3 アクセスを同じコンピュートリソース上で安定して共存させるための重要な改善です。

**従来の課題**

Mountpoint は S3 をファイルシステムとしてマウントするツールですが、従来は時間とともにメモリ使用量が増加する可能性があり、特にメモリリソースが限定されたコンテナ環境では OOMKiller によってプロセスが強制終了されるリスクがありました。また、機械学習ワークロードのように GPU メモリやシステムメモリを大量に消費するアプリケーションと競合すると、パフォーマンス低下や安定性の問題が発生していました。

**メモリ制御のアプローチ**

新機能では、メモリ上限を2つの方法で設定できます：

1. **手動設定**: ユーザーが明示的にメモリ上限値を指定
2. **自動検出**: 実行環境（特に Amazon EKS コンテナ）に基づいて安全なデフォルト値を自動判定

Amazon EKS で実行する場合、Mountpoint はコンテナに割り当てられたメモリ予算を自動検出します。これにより、Pod のリソース制限（`resources.limits.memory`）と整合性のあるメモリ配分が自動的に適用されます。

**メモリ不足時の挙動**

メモリ使用量が上限に近づくと、Mountpoint は操作速度を意図的に遅延させ、予算内に収まるように調整します。これは、プロセスをクラッシュさせるのではなく、スループットを制御することで安定性を優先する設計です。I/O レイテンシーは増加する可能性がありますが、アプリケーション全体のメモリ不足による障害を回避できます。

**実装シナリオ**

機械学習のトレーニングジョブでは、大量のトレーニングデータを S3 から読み込みながら、GPU メモリとシステムメモリを最大限に活用する必要があります。従来は S3 からローカルディスクへの事前コピーが必要でしたが、Mountpoint のメモリ制御機能により、直接 S3 マウントしながらメモリ予算を守ることが可能になります。例えば、16GB のメモリを持つコンテナで、12GB を ML モデルに、残り 4GB のうち 2GB を Mountpoint に割り当てる、といった厳密な配分が実現できます。

設定の詳細やパラメータについては、Mountpoint for Amazon S3 の公式ドキュメントを参照してください。コンテナ環境での実装例や、メモリ制限下でのパフォーマンス特性についても記載されています。

## SRE視点での活用ポイント

**DocumentDB バックアップのクロスリージョン対応**

SRE の観点では、DocumentDB のクロスリージョンバックアップ機能は、障害対応ランブックに直接組み込むべき要素です。リージョン障害は稀ですが、発生時の影響は甚大であり、事前にバックアップからの復旧手順を整備しておくことで RTO を大幅に短縮できます。

Terraform で AWS Backup のリソースを管理している環境であれば、クロスリージョンコピールールを IaC で定義し、バックアップポリシーのバージョン管理とコードレビューを通じて品質を担保できます。また、論理的にエアギャップされたコンテナをマルチアカウント環境で運用する場合、AWS RAM を活用して「バックアップ専用アカウント」を分離することで、本番アカウントが侵害されてもバックアップの整合性を保護できます。

導入時の判断基準としては、まずビジネスクリティカルな DocumentDB クラスタを対象とし、バックアップ転送コストとストレージコストを見積もります。コンプライアンス要件（GDPR、金融規制など）でデータレジデンシーが厳格な場合は、コピー先リージョンを慎重に選定する必要があります。

**Mountpoint のメモリ制御**

Mountpoint for Amazon S3 のメモリ制御機能は、特に Kubernetes クラスタで複数のワークロードを密に配置している環境で価値を発揮します。CPU と同様にメモリも限られたリソースであり、Pod のメモリリクエストとリミットを適切に設定することが安定運用の基本です。Mountpoint がメモリ予算を自動検出・遵守できるようになったことで、S3 アクセスを伴うバッチ処理やデータパイプラインを、より高密度にスケジューリングできるようになります。

導入時のリスクとしては、メモリ制限によって I/O スループットが低下する可能性があるため、事前に実ワークロードでベンチマークを実施し、メモリ割り当てと I/O 性能のトレードオフを把握しておくことが重要です。CloudWatch でメモリ使用率とディスク I/O メトリクスを監視し、必要に応じてメモリ上限を調整する運用フローを確立すると良いでしょう。

## まとめ

今回のアップデートでは、データ保護とコンプライアンス対応を強化する AWS Backup の機能拡張、新世代 EC2 インスタンスの展開拡大、そしてコンテナ環境でのリソース管理を改善する Mountpoint のメモリ制御機能など、多岐にわたる改善が含まれています。特に SRE にとって重要なのは、障害復旧戦略の選択肢が広がったこと、そして限られたリソースをより効率的に活用できるようになった点です。

EC2 インスタンスの新世代（C8id/M8id/R8id）は、単なるスペックアップではなく、帯域幅の動的調整機能により、ワークロードの特性に応じた細かいチューニングが可能になりました。これにより、コストとパフォーマンスのトレードオフをより精密にコントロールできます。

また、Lambda MicroVMs の PrivateLink 対応は、規制対象ワークロードをクラウドネイティブに構築する上での重要な一歩となります。完全プライベートなネットワークアーキテクチャで、サーバーレスの俊敏性と厳格なセキュリティ要件を両立できるようになりました。

全体として、今回のアップデートは「運用の柔軟性」「セキュリティ強化」「リソース最適化」という3つの軸で AWS の成熟度を高めるものであり、エンタープライズ環境でのクラウド活用をさらに推進する内容となっています。
